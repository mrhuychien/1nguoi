1. Tại sao cần thay đổi tư duy?

❌ Cách cũ: "AI làm theo lệnh"
Bạn có ý tưởng → Bạn mô tả chi tiết → AI thiết kế theo → AI code

• Bạn phải biết mọi thứ trước (layout, màu sắc, tính năng...)

• AI chỉ biết những gì bạn nói, bỏ qua những gì bạn không biết hỏi

• Kết quả phụ thuộc vào khả năng mô tả của bạn

✅ Cách mới: "AI & Human là cộng sự"
Bạn nêu mục tiêu → AI đề xuất vision → Bạn cung cấp context → Cùng điều chỉnh → AI code

• AI đã "thấy" hàng triệu project, biết pattern nào hiệu quả

• Bạn chỉ cần biết MỤC TIÊU và CONTEXT của mình

• Kết quả là sự kết hợp: chuyên môn của AI + thực tế của bạn

3. Năm nguyên tắc vàng v4.0

1 "AI đề xuất trước, hỏi sau"
❌ SAI: "Chào bạn! Để bắt đầu, cho tôi biết: 1. Bạn bán gì?..."
✅ ĐÚNG: "Với landing page, tôi đề xuất ngay vision này: [...] Để customize, tôi cần biết context..."
2 "Human cung cấp context, không phải giải pháp"
❌ SAI: "Tôi muốn hero có gradient xanh-tím, font Montserrat..."
✅ ĐÚNG: "Khách hàng của tôi là Gen Z, thích style bold và trendy."
3 "Một giờ Vision tiết kiệm mười giờ Refine"
BƯỚC 1+2 (Vision + Context):     30-60 phút đầu tư
BƯỚC 3+4 (Blueprint + Contract): 15-30 phút
BƯỚC 5 (Build):                  AI làm 5-15 phút
BƯỚC 6 (Refine):                 5-15 phút (nếu Vision tốt)
                                 2-5 giờ (nếu Vision kém)
4 "Blueprint là khế ước"

SAU BƯỚC 3 (Blueprint approved):

✓ Có thể: Đổi text, màu sắc nhỏ, nội dung trong section

✗ Không thể: Thêm section, đổi layout, đổi tech stack

Muốn thay đổi lớn? → Quay lại BƯỚC 1

5 "Thợ xây không được phép sáng tạo"

Thợ xây PHẢI:

✓ Code đúng 100% theo Blueprint

✓ Hỏi khi gặp conflict kỹ thuật

✓ Báo cáo tiến độ

Thợ xây KHÔNG ĐƯỢC:

✗ Tự quyết định thay đổi design

✗ Thêm features "có vẻ hay"

✗ Dùng tech stack khác

→ Mọi sáng tạo xảy ra ở BƯỚC 1-3, không phải BƯỚC 5

VISION

Kiến trúc sư detect & đề xuất • 🤖 AI-led

Quy trình:
  1. 1. AI detect loại project (Landing, SaaS, Dashboard, Blog, Portfolio)
  2. 2. AI đề xuất vision hoàn chỉnh với layout diagram
  3. 3. AI đề xuất style (typography, colors, animations)
  4. 4. AI đề xuất tech stack phù hợp
Output mẫu:
Chào Chủ nhà! 👋

Tôi detect đây là [LOẠI PROJECT].
Đây là VISION tôi đề xuất:

📐 LAYOUT ĐỀ XUẤT
[Layout diagram]

🎨 STYLE ĐỀ XUẤT
[Style suggestions]

💻 TECH STACK
[Tech recommendations]

Đây là template TỐT cho 80% projects.
2

CONTEXT

Chủ nhà cung cấp • 👤 Human-led

Context Questions:

1. Sản phẩm/dịch vụ: Mô tả ngắn gọn bạn đang làm gì?

2. Khách hàng mục tiêu: Ai sẽ sử dụng? (tuổi, nghề, pain point)

3. Brand: Đã có guidelines? Hay cần đề xuất?

4. Khác biệt: Có gì khác so với vision đề xuất?

5. Constraints: Deadline, tech limits, yêu cầu đặc biệt?

Sau khi nhận context:
Cảm ơn context!

Tôi ĐIỀU CHỈNH vision:

📍 THAY ĐỔI:
• [Thay đổi 1 - lý do]
• [Thay đổi 2 - lý do]

📍 GIỮ NGUYÊN:
• [Phần phù hợp]

📍 ĐỀ XUẤT THÊM:
• [Gợi ý dựa trên context]

Đồng ý? Nếu OK → BLUEPRINT.
3

BLUEPRINT

Đồng thuận chi tiết • 🤝 Collaborative

Blueprint bao gồm:

• Project Info (tên, loại, ngày, version)

• Mục tiêu (Primary Goal, Target Audience, Key Message)

• Cấu trúc Sections chi tiết

• Design System (Colors, Typography, Spacing)

• Tech Specifications

• File Structure

• Responsive Breakpoints

• Checkpoint xác nhận

Blueprint Checkpoint:
✅ BLUEPRINT CHECKPOINT

Chủ nhà xác nhận:
- [ ] Layout sections đúng mong muốn
- [ ] Màu sắc/font phù hợp brand
- [ ] Không thiếu section quan trọng
- [ ] Tech stack OK

⚠️ SAU KHI XÁC NHẬN, KHÔNG THỂ
   THAY ĐỔI LỚN.

Reply "APPROVED" để tiếp tục.
4

CONTRACT

Tóm tắt cam kết • 🤝 Collaborative

✅ DELIVERABLES (Sẽ nhận được):

• Landing Page / App / Dashboard (responsive)

• [Số] sections như Blueprint

• Animations (subtle scroll reveals)

• Dark Mode (Không / Có)

• Source Code (full access)

⚠️ KHÔNG BAO GỒM:

❌ Backend / Database (tùy project)

❌ Authentication

❌ Payment integration

❌ CMS / Admin panel

❌ Hosting setup

Reply "CONFIRM" để nhận CODER PACK
5

BUILD

CODER PACK cho Thợ xây • 🤖 AI-led

CODER PACK bao gồm:

• Vai trò Thợ xây + Quy tắc tuyệt đối

• Blueprint đầy đủ

• Files cần tạo (package.json, tailwind.config, etc.)

• Design Tokens (colors, fonts)

• Instructions sau khi hoàn thành

Quy tắc tuyệt đối cho Thợ xây:
1. KHÔNG thay đổi kiến trúc / layout
2. KHÔNG thêm features không có trong BP
3. KHÔNG đổi tech stack
4. Gặp conflict → BÁO CÁO, không tự quyết

Hỏi DUY NHẤT:
"Bạn muốn lưu dự án ở đâu?"

Sau đó → TIẾN HÀNH NGAY.
6

REFINE

Tinh chỉnh chi tiết • 🤝 Collaborative

✅ CÓ THỂ REFINE:

• Thay đổi text/copy

• Điều chỉnh màu sắc nhỏ

• Thêm/bớt nội dung trong section có sẵn

• Sửa lỗi hiển thị

❌ KHÔNG THỂ (cần quay lại BƯỚC 1):

• Thêm section hoàn toàn mới

• Đổi layout/structure

• Thay đổi tech stack

• Thêm features lớn

Cách yêu cầu: "Refine: [Mô tả cụ thể cần thay đổi]"

📋 Quy trình làm việc chi tiết

1. Bạn (A) → Trợ lý (B): "Tôi muốn X"
2. Trợ lý (B) → Bạn (A): Vẽ bản thiết kế (Vision + Blueprint)
3. Bạn (A) → Trợ lý (B): "XÁC NHẬN LƯU" hoặc "Sửa lại phần Y"
4. Trợ lý (B) → Thợ xây (C): Hướng dẫn chi tiết + Danh sách cam kết
5. Thợ xây (C) → Trợ lý (B): Code + Báo cáo theo mẫu
6. Trợ lý (B) → Bạn (A): Kiểm tra kết quả, đối chiếu cam kết
7. Bạn (A): "XÁC NHẬN XONG" → Chuyển phần tiếp theo

🎨 Frontend Aesthetics Skill

Core UI/UX skill for creating distinctive, polished interfaces. Prevents "AI slop" - generic designs.

Typography

❌ Avoid Generic:

Arial, Helvetica, Inter (overused), Roboto, Open Sans

✅ Recommended:

Display: Cal Sans, Instrument Serif, Space Grotesk
Body: Plus Jakarta Sans, Outfit, Satoshi, DM Sans
Color System

💡 Use hsl() function:

/* CORRECT */
--color-primary: hsl(220, 100%, 60%);
--color-surface: hsl(230, 30%, 15%);

/* WRONG - Missing hsl() wrapper */
--color-primary: 220 100% 60%;

❌ Avoid:

Purple-to-pink gradients (AI cliche), Neon colors without purpose

Motion & Animation
/* Card hover - subtle lift */
.card-hover:hover {
  transform: translateY(-4px);
  box-shadow: 0 12px 24px -8px rgba(0, 0, 0, 0.15);
}

/* Duration: 150-300ms for micro, 300-500ms for macro */
/* Always respect prefers-reduced-motion */
Backgrounds & Depth
/* Glassmorphism card */
.glass-card {
  background: rgba(255, 255, 255, 0.05);
  backdrop-filter: blur(12px);
  border: 1px solid rgba(255, 255, 255, 0.1);
}

/* Dot pattern */

  circle, rgba(255, 255, 255, 0.1) 1px,
  transparent 1px
);
background-size: 24px 24px;

♿ Accessibility (WCAG AA) Skill

Ensure interfaces are usable by everyone, meeting WCAG 2.1 AA standards.

Color Contrast

• Normal text (<18px): 4.5:1

• Large text (≥18px bold): 3:1

• UI components: 3:1

Keyboard Navigation

• Never remove focus outline without replacement

• Use :focus-visible for custom styles

• Ensure logical tab order

Semantic HTML

• Use correct elements: button, a, nav, main

• Logical heading hierarchy (h1 → h2 → h3)

• Proper alt text for images
